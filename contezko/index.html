Contezko is the enterprise edition of BankOfEuler, the public-domain zero-knowledge banking server. The ledger stores only encrypted values. The bank never learns a balance. Each transfer carries a proof that it is valid, and the server verifies the proof. A treasury settlement and a one-cent micropayment are verified the same way.

A ledger with nothing in it

BankOfEuler was designed on one principle: the server should be able to do its job without learning a single quantity.
Contezko keeps that principle and adds what an enterprise deployment requires.

Homomorphic ledger

Values are stored under ElGamal encryption. The server combines ciphertexts into encrypted sums and differences without ever decrypting them. The server cannot produce a balance, for its operator or for anyone else.

Proofs of non-negativity

When a value is subtracted, the client convinces the server through an interactive proof that the difference is not negative, so an overdraft cannot be represented.

Equal scrutiny

Micropayments are verified with the same proof as any other transfer. There is no minimum amount and no reduced check for small amounts.

Shared proof construction

Two parties can construct a proof together, which enables provably fair games of chance. A reference coin-flipping service, flipserve, is included in every deployment.

Values as existence

A value is an empty file whose name is a secure hash of gx. The existence of the file confirms the value of x. The file has no contents and the server has no key, so there is nothing on the server that can be read.

Transport

All sessions run over stunnel. Client authentication is unnecessary, since the client proves what it needs to prove, but the channel is encrypted to thwart eavesdroppers.

Proof of non-negativity, live

A withdrawal is a subtraction the bank cannot see. Enter a balance and a withdrawal: the bank receives only commitments, forms the encrypted difference itself, and accepts the withdrawal only if the client can prove that difference is not negative.
Simplified for the browser; the production protocol is interactive and the prover's witnesses never leave the client.

Commitments are gx mod p with p = 261 − 1 and g = 3, the same shape as the hashes that name BankOfEuler's value files. The proof uses Lagrange's theorem: every non-negative integer is a sum of four squares, and no negative integer is.

Three centuries of number theory

BankOfEuler is named for Leonhard Paul Euler (1707–1783), who established that xφ(n) ≡ 1 (mod n).

Quadratic residuosity, visualized

The Contezko mark is produced by qrspiral, a tool shipped with BankOfEuler that plots the Jacobi symbol of successive integers along a spiral for a chosen modulus. The pattern is determined by the modulus. The copy above was computed in your browser for modulus …; every visit chooses another.

The same arithmetic underlies the proofs of non-negativity: a client demonstrates a property of a hidden number by exhibiting its relationship to squares modulo n, and the server verifies the relationship without learning the number.

Operations

bankshell is the command-line client.
It sends each operation to the server and records the result locally once the server has accepted it.

CommandEffectNote
bankshell sync -a 0x75 '$10'Make the shell aware of a value held in an account.Accounts are directories; values are files.
bankshell check -a 0x75 '$10'Confirm the server still values the number.Reports "has value" or does not.
bankshell split -a 0x75 '$10' '$2'Split a value into two values that sum to it.The $10 file ceases to have value.
bankshell mergeCombine two values into their sum.The parts are unlinked on success.
bankshell randomizeSplit a value into a valuable part and a worthless part.The worthless part is discarded locally; the server retains it as an ordinary value.

Sandbox

A BankOfEuler server is running at bank.contezko.com. Account 0x75 holds one $10 value, shared with everyone and reset on the hour.

The enterprise branch builds with current compilers and installs into ~/.BankOfEuler, including the sandbox configuration and server certificate. It needs libgmp-dev and Python 3. The session runs over the bank's own TLS, carried inside a WebSocket; the server certificate is verified end to end.

Security

Contezko is built on foundational principles of number theory studied continuously since the eighteenth century.

Established foundations

Every proof in the system reduces to Euler's theorem and the hardness of the discrete logarithm, the same assumptions that secure the world's public-key infrastructure.

Zero disclosure by design

The server holds ciphertexts and hashes only. A copy of the server's storage contains no balances, transaction amounts or account relationships.

Soundness

A transfer is accepted only when its proof verifies. A client cannot spend a value it does not hold, create value, or overdraw.

Encrypted transport

Every session runs over an encrypted stunnel channel, which protects it against eavesdropping and tampering.

Durable records

Every operation is journaled on the server before and after it is applied. Multi-step transactions can be audited and reconciled from the journal alone, with no dependence on client state.

Open source, open review

The reference implementation is public domain and has been available for review in full since its first release. Contezko Enterprise ships the same code, with the same proofs, under support.
